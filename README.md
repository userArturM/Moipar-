# Bitora password 4.6.1

Локальный менеджер паролей для Windows с тёмной и светлой темами, категориями,
генератором, аудитом, TOTP, импортом и зашифрованными резервными копиями.
Хранилище использует AES-256-GCM и scrypt; формат passvault v2 сохранён.

## Скачать и установить

Готовые файлы: https://github.com/userArturM/Moipar-/releases/latest
Скачайте Bitora-password-Setup.exe или Bitora-password-portable.zip.
Дополнительные артефакты остаются в успешном Windows build в GitHub Actions:
- Bitora-password-Setup — установщик.
- Bitora-password-portable — приложение без установки.
- MoiParoli-BrowserHost — комплект браузерной интеграции.
- MoiParoli-checksums — размеры файлов и контрольные суммы SHA-256.

Закройте старую программу, включая значок в трее, прежде чем обновлять.
Установщик использует прежний AppId. Данные расположены отдельно от программы
в пользовательской папке APPDATA/MoiParoli или в выбранной папке хранилища.
Перед обновлением сохраните отдельную копию vault.dat и ключевого файла.
Удаление приложения не удаляет пользовательское хранилище.

## Расширение Chrome / Яндекс

1. Установите выпуск 4.5. Установщик автоматически регистрирует связь с Chrome, Яндекс, Edge и Chromium для текущего пользователя.
2. Откройте страницу расширений браузера и включите режим разработчика.
3. Загрузите папку browser_extension из каталога установки. Постоянный ID: odddlefcmbmjphfnglidnmdpdlofmfgn. Старое расширение с другим ID замените новой папкой.
4. Нажмите «Проверить подключение» в расширении. При ошибке: приложение → Инструменты → Браузеры → Восстановить подключение.

Для portable распакуйте весь архив в постоянную папку и восстановите подключение
из приложения. EXE приложения и browser_host.exe должны оставаться вместе.
После переноса папки повторите восстановление.

На HTTPS-сайте кнопка «Заполнить данные» запрашивает мастер-пароль в отдельном
окне Windows; при нескольких аккаунтах предлагает выбор. Форма не отправляется.
Кнопка «Сохранить с сайта» читает логин и пароль из видимых полей и открывает
нативное окно подтверждения. Новый пароль сохраняется в категорию «Из браузера»;
смена пароля того же логина обновляет запись с сохранением истории.

«Предлагать сохранение на этом сайте» отдельно запрашивает разрешение для данного
HTTPS-сайта. После отправки формы появляется окно подтверждения сохранения.
Расширение хранит только предпочтения сайтов, а не пароли. Мастер-пароль не
передаётся браузеру. Отмена не изменяет хранилище.
Домен должен совпадать точно; iframe и нестандартные HTTPS-порты не поддерживаются.
Расширение пока устанавливается вручную, оно не опубликовано в магазинах.

## Windows Hello

Настройки → Windows Hello: включить / отключить. Для включения нужны мастер-пароль
и подтверждение Windows. В EXE включён нативный компонент, использующий
IUserConsentVerifierInterop с HWND окна приложения.

Это экспериментальный быстрый вход. Секрет защищён DPAPI текущего пользователя,
но не привязан аппаратно к жесту Hello. Проверка PIN/биометрии на устройствах
Windows 10/11 ещё требуется. При недоступности компонента используйте мастер-пароль.

## Резервные копии

Файл → Экспорт зашифрованной копии. При восстановлении программа сначала проверяет
расшифровку копии с её мастер-паролем и ключевым файлом, если он нужен.
Прежний файл сохраняется как vault.dat.before-restore.
CSV-экспорт содержит открытые пароли; храните его только до завершения переноса.

## Разработка и проверки

```powershell
py -m pip install cryptography pystray pillow openpyxl pyinstaller
py -m unittest discover -s tests -v
node tools/test_extension.mjs
py moi_paroli.py
```

Сборка выполняется через .github/workflows/build.yml. Она запускает тесты,
компилирует компонент Hello, собирает EXE и установщик, проверяет PE-заголовки,
Native Messaging через настоящий EXE и публикует контрольные суммы.

## Ограничения выпуска

В 4.3 обновлён интерфейс: спокойная светлая тема, синий акцент, скруглённые карточки
и единые стили. Сохранены тёмная тема, новая иконка и ручное разрешение конфликтов:
Инструменты → Разрешить конфликты. Можно выбрать локальную запись, запись с диска
или сохранить обе с отдельными идентификаторами. Пароли в сравнении скрыты.

Проверки интерфейса включают масштабы Tk 125–200%, длинные записи и переход
к поиску/между элементами с клавиатуры.
На узком окне и при крупном масштабе доступны вкладки «Разделы», «Записи»,
«Подробности»; окна ввода прокручиваются и показывают элемент, получивший фокус.
Проверки Chrome выполняются в изолированной
сессии на тестовых HTTPS-страницах с подставным ответом Native Messaging;
В установочном тесте настоящее расширение также соединяется с собранным EXE
через Native Messaging и проверяет версию и поддержку сохранения.
Тест обновления использует прошлый установщик 4.1 из Actions, если артефакт
ещё доступен, и проверяет сохранность тестовых записей, вложений, настроек и копий.
Если старый артефакт истёк, проверяется повторная установка текущей версии.

EXE пока не подписаны: нужен сертификат подписи владельца.
Не завершены проверки биометрии и пользовательских профилей Chrome/Яндекс
на реальных устройствах. Установка, обновление и удаление проверяются в CI. Независимый аудит безопасности
не проводился. Автотесты не заменяют эти проверки.

## Выпуск 4.4

- Плавное появление окна при запуске и открытии хранилища. Анимация отключается в настройках.
- Русский / English: переключатель на экране входа и в настройках. Язык сохраняется; записи не переводятся.
- Мастер-пароль от 4 символов при создании и смене. Для защиты данных рекомендуется длинная уникальная фраза.
- Удаление категории: правая кнопка мыши по категории или Инструменты → Удалить категорию. Записи остаются без категории, включая записи в корзине.
- Восстановлена иконка окна / панели задач; расширение получает ту же иконку в размерах 16, 32, 48 и 128 пикселей.
- Обновления: сначала GitHub Releases, затем последняя успешная сборка Windows build на main. Версия читается из исходника именно этой сборки; неудачные сборки не предлагаются.

Приватный репозиторий требует авторизации GitHub API. В настройках можно указать
fine-grained токен с доступом к этому репозиторию и разрешениями Contents: Read,
Actions: Read. Токен сохраняется отдельно от settings.json, зашифрован Windows
DPAPI для текущего пользователя. Пустое поле сохраняет прежний токен; кнопка
«Удалить токен» удаляет его. Токен не добавляется в URL и не записывается в логи.
Без доступа программа сообщает об этом и предлагает открыть Actions в браузере;
она не объявляет установленную версию последней. Обновление устанавливается вручную.

## Выпуск 4.5

В Инструментах доступны управление категориями (создание, переименование,
цвет, значок) и центр резервных копий. Для переноса нескольких записей выделите
их с Ctrl/Shift и нажмите «Перенести выбранные». Удаление категории сохраняет записи.

Поиск объединяет слова через И. Кавычки задают фразу. Примеры:
`github artur`, `category:Работа`, `tag:важное`, `is:weak`, `is:reused`,
`is:old`, `is:empty`, `is:favorite`. Пароли не включены в поисковый индекс.
Свернуть боковую панель можно кнопкой ☰, размер текста меняется в настройках.

Центр резервных копий показывает даты локальной и отдельной копий. При отсутствии
отдельной копии или её возрасте от 7 дней появляется напоминание не чаще раза
в день; его можно отключить. Проверка восстановления работает с временной копией
и не заменяет рабочее хранилище. Отдельную копию следует размещать на другом диске;
программа не может гарантировать физическую независимость выбранной папки.

Окно обновлений показывает версию и изменения. Установщик из Releases скачивается
в выбранный файл; до замены файла обязательно проверяется SHA-256 из GitHub API.
Неудачная загрузка или несовпадение хеша не заменяет прежний файл. Установщик
автоматически не запускается. Для старых сборок Actions открывается их страница.

Расширение поддерживает составной autocomplete, регистрацию, новый пароль,
кнопки JavaScript и сохранение имени при двухэтапном входе. Имя временно хранится
только в памяти фонового процесса (до 3 минут, в пределах вкладки и HTTPS-сайта).
Оно может сброситься при выгрузке фонового процесса браузером. В нативном окне
логин можно исправить перед сохранением. Новые пароли не подставляются автоматически
в поля смены пароля. Пароли не записываются в хранилище браузера расширения.

Тестовые DOM-сценарии прошли в Chrome и Яндекс. Служебное соединение Яндекса
с установленным модулем 4.5.1 подтверждено; тест загрузки расширения использует
браузерный DevTools API. В CI проверяется соединение установленного расширения
с собранным host в Chromium. Сохранение и заполнение с реальным PIN в новой
версии требует ручной проверки на устройстве пользователя.
Пользователь подтвердил вход через PIN в основном приложении; браузерное подтверждение новой версии требует отдельной ручной проверки.
Отмена, недоступность, смена мастер-пароля, сигнал блокировки сеанса и поздний ответ
Hello проверяются автоматическими тестами; поздний ответ не разблокирует новую сессию.

## Подпись издателя

Сертификата пока нет, поэтому текущий выпуск остаётся неподписанным. В workflow
подготовлены подпись SHA-256, RFC 3161 timestamp и проверка Authenticode через
Windows SDK SignTool. Для подключения подходящего экспортируемого сертификата
добавьте GitHub Actions secrets `MOIPAROLI_SIGNING_PFX_BASE64` и
`MOIPAROLI_SIGNING_PASSWORD`. Приватный ключ не включается в репозиторий и артефакты.
Для сертификата в аппаратном ключе или сервиса подписи потребуется соответствующий
провайдер. Самоподписанный сертификат вместо сертификата издателя не создавался.

## Выпуск 4.5.2: полная браузерная связка

Подтвердить сохранение или заполнение теперь можно в отдельном окне через
Windows Hello либо мастер-паролем. Windows Hello доступен, если он заранее
включён в приложении для выбранного хранилища без ключевого файла. PIN вводится
только в системном окне Windows. Мастер-пароль не передаётся расширению.

Запросом управляет фоновая часть расширения: закрытие всплывающего окна
не останавливает сохранение или заполнение. Перед заполнением повторно
проверяются активная вкладка и её адрес. Пароль не сохраняется в браузерном
хранилище расширения; ответ всплывающему окну содержит только результат операции.

Если хранилище открывается через PIN, а мастер-пароль не принимается,
можно выбрать Файл → «Сменить мастер-пароль через Windows Hello…».
Требуется новое подтверждение Windows Hello; новый пароль задаёт пользователь.
После смены ключа Windows Hello нужно настроить заново. Старые резервные копии
остаются зашифрованы прежним паролем. Хранилище не сбрасывается в пустое.

## Выпуск 4.5.3: крупный масштаб и пакет магазина

Экран входа, создания хранилища и окно подтверждения заполнения прокручиваются.
Клавиатурный переход показывает активный элемент. Проверяются масштабы 125–200%
в обоих языках и для нового и существующего хранилищ. Распознанные браузером
платёжные поля исключены из чтения и заполнения.

В Releases доступен MoiParoli-store-kit.zip: внутри ZIP для загрузки в магазин,
скриншоты, иконка, промоизображение и описания. Пакет создаётся по белому списку
файлов, без хранилищ, токенов и приватных ключей. ZIP воспроизводим.
Для публикации нужны аккаунт разработчика и завершение привязки ID магазина.
См. [материалы магазина](STORE_LISTING.md), [политику конфиденциальности](PRIVACY.md)
и [подготовку подписи](SIGNING.md). Пакет не отправлялся на модерацию.

## Выпуск 4.6.0: браузерная связь и восстановление

- В расширении: отдельные карточки действий, последнего результата и проверки подключения, светлая и тёмная темы. Диагностика сравнивает версии и поддержку сохранения/заполнения.
- Последний результат вкладки переживает закрытие окна расширения и перезапуск его фонового процесса. Только общий статус, тип и время операции хранятся в памяти сеанса: без URL, логина и пароля. Переход на другой адрес и закрытие вкладки удаляют статус.
- В приложении: «Инструменты → Браузеры: подключение и диагностика» проверяет регистрацию и настоящий ответ модуля, показывает версии. Наличие расширения проверяется из самого браузера.
- «Резервные копии → Просмотреть и восстановить отдельные записи…» проверяет пароль копии, показывает дату и записи. Выбранные записи добавляются как новые с историей и вложениями, существующие не заменяются.
- При удалении категории можно оставить записи без категории или отправить в корзину. Категория восстанавливается через «Корзина категорий»; последующие правки записей не перезаписываются. Удаление записи и категории можно отменить из уведомления.
- «Объединить дубли…» ищет одинаковый сайт и логин, предлагает выбрать источник каждого поля; пароли не показывает. Вложения объединяются, история паролей сохраняется в пределах обычного лимита, другие версии остаются в корзине. Если данные изменились после сравнения, объединение отклоняется.
- Поиск поддерживает `site:example.com login:user note:"текст заметки"` и русские аналоги `сайт:`, `логин:`, `заметка:`. Пароли в поиске не участвуют.
- Новые окна приложения переведены на английский и используют общий прокручиваемый интерфейс.

Живая проверка на компьютере владельца: сохранение тестовой записи в Яндексе подтверждено владельцем; обратное заполнение после ручного Windows Hello подтверждено точным совпадением обоих полей. Проверка выполнялась с закрытым окном расширения. Настоящий мастер-пароль и PIN в тестовый сценарий не передавались.

## Bitora password 4.6.0 — Midnight

Приложение переименовано в **Bitora password**. Используется предоставленный владельцем синий логотип с буквой B и замочной скважиной: значок Windows, трей, вход, установщик и расширение.

Главный экран следует выбранному Midnight: глубокая тёмная палитра, спокойный мятный акцент, узкая навигация слева, список записей и отдельная карточка данных. Категории и теги выбираются над списком; полная библиотека раскрывается кнопкой «Категории». Панель аудита открывается через меню, а не занимает главный экран. Крупный текст и небольшое окно переключают список и подробности во вкладки. Карточка данных прокручивается колесом; длинные значения переносятся, сохраняя место для кнопок.

После первого запуска 4.6.0 включаются Midnight и свёрнутая библиотека. Позднее выбранная пользователем светлая тема сохраняется. Язык, размер текста, хранилище, ключевой файл, резервные копии и настройки безопасности сохраняются.

Для совместимости остаются прежними AppId установщика, папка установки, внутреннее имя MoiParoli.exe, каталог данных MoiParoli, криптографические привязки Windows Hello, ID расширения и имя Native Messaging. Это обновление существующей программы. Новое отдельное пустое хранилище из-за переименования не создаётся. Старые установленные ярлыки заменяются именем Bitora password.

Основные файлы выпуска — Bitora-password-Setup.exe, Bitora-password-portable.zip и Bitora-password-store-kit.zip. Совместимые имена MoiParoli также публикуются, чтобы старые версии могли скачать обновление. Новый клиент предпочитает файл с именем Bitora.

## 4.6.1 — элементы Midnight вместо стандартной таблицы

Главный список заменён на двухстрочные записи с монограммами и округлённым выделением. Навигация использует единые контурные иконки и кнопки, отрисованные для Midnight. Категории доступны компактными переключателями, поиск расположен рядом; расширенные фильтры раскрываются по запросу. Убрана отдельная строка меню. Карточка содержит монограмму, домен, отдельные поля логина и пароля; дополнительные действия собраны в меню «Ещё».

Сохранены мышь, клавиатура, Ctrl/Shift для множественного выбора, поиск, контекстное меню и работа с существующим хранилищем. Список рисует только видимые строки. Пользователь проверил отдельный нативный предпросмотр на вымышленных записях и подтвердил, что интерфейс стал ближе к выбранному Midnight.
