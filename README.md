# Мои пароли Pro 4.0 — промежуточная версия исходников

> Не является полным релизом Pro 4.0. Перед обновлением сохраните отдельную копию `vault.dat` и ключевого файла, если он используется.

## Реализовано и проверено автоматическими тестами

- Сохранён существующий формат `passvault` v2 (AES-256-GCM/scrypt, прежняя структура JSON).
- При одновременном изменении одной записи на разных устройствах сохранение отменяется с `SyncConflict`, вместо тихой перезаписи.
- `Vault.validate_backup(path, password, keyfile)` проверяет расшифровку копии.
- При блокировке UI очищается буфер обмена, если в нём ещё содержится скопированный программой текст.
- Автоввод при передаче HWND проверяет, что фокус не переместился на другое окно.
- Добавлены пять тестов формата, неверного пароля, копии и синхронизации.

## Запуск и тестирование

```powershell
py -m pip install cryptography pystray pillow openpyxl
py -m unittest discover -s tests -v
py moi_paroli.py
```

## Сборка Windows

GitHub Actions: `.github/workflows/build.yml`. Перед PyInstaller теперь выполняются тесты. При успешной сборке артефакты доступны в Actions: `MoiParoli-portable` и `MoiParoli-Setup`. EXE в этом архиве нет, Windows-сборка в текущем окружении не проводилась.

## Не готово

- Расширения для Chrome/Яндекс Браузера и защищённый Native Messaging.
- Windows Hello и новая система управления устройствами.
- Полная переработка интерфейса и GUI-тестирование на Windows.
- Независимые security-аудит и проверка миграции на реальном пользовательском `vault.dat`.

При ошибке `SyncConflict` сохранение прерывается, чтобы не потерять данные; ручное разрешение конфликтов ещё не добавлено.

## Дополнение: интеграция с браузером (экспериментальная)

Добавлены `browser_extension/` (Manifest V3, Chrome/Яндекс) и `browser_host.py`
(Native Messaging). Это не фоновая синхронизация и не автоматическая установка расширения.
Каждый запрос требует явного нажатия кнопки расширения, проверки HTTPS-домена и
ввода мастер-пароля в **отдельном окне Windows**. Сам мастер-пароль не попадает в браузер.
При совпадении нескольких аккаунтов заполнение блокируется (без автоматического выбора).
Записи сопоставляются по **точному доменному имени**, а не по частичному совпадению;
переход на субдомен требует отдельной записи.

### Сборка/установка на Windows (проверить вручную)

1. Запустить Windows-сборку в GitHub Actions. Артефакты `MoiParoli-portable`,
   `MoiParoli-Setup` и `MoiParoli-BrowserHost` создаются только если job завершится успешно.
2. Установить программу либо распаковать `MoiParoli-BrowserHost`, так чтобы
   `browser_host.exe` и `register_browser_host.ps1` находились рядом.
3. В Chrome или Яндекс Браузере открыть страницу расширений и включить режим разработчика.
   Выбрать «Загрузить распакованное расширение», указать папку `browser_extension`.
4. Скопировать 32-символьный ID расширения и выполнить в PowerShell из каталога
   с `browser_host.exe`:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\register_browser_host.ps1 -ExtensionId ВАШ_ID
   ```
5. Перезапустить браузер, открыть HTTPS-сайт, нажать расширение и дать однократное
   разрешение в открывшемся окне. Поля заполняются без отправки формы.

**Важные ограничения:** динамические/вложенные формы, iframe, страницы без HTTPS,
несколько аккаунтов одного домена пока не поддерживаются; при компрометации расширения
секреты, передаваемые ему для заполнения, могут быть перехвачены. Устанавливайте только
свои проверенные исходники. Расширение не публиковалось в магазинах.

## Проверки, вошедшие в архив

- 5 регрессионных тестов хранилища из предыдущей промежуточной версии.
- 5 тестов протокола Native Messaging, валидации HTTPS и точного совпадения домена.
- Команда: `python -m unittest discover -s tests -v`.

## Что пока НЕ реализовано

- Windows Hello (требует привязки ключа к защищённому хранилищу Windows и модели восстановления).
- Полная переработка GUI; существующая тёмная/светлая тема осталась прежней.
- Безопасный выбор из нескольких аккаунтов, автоматическая установка расширения,
  полноценное покрытие тестами UI и сборка EXE непосредственно в текущем окружении.
- Ручное разрешение конфликтов синхронизации и независимая проверка безопасности.

**Перед реальным использованием:** создать офлайн-копию `vault.dat`, испытать на
тестовом хранилище и выполнить проверку Windows-сборки и поведения расширения.

## Дополнение от 14.10.2026 — выбор аккаунта

Native Messaging теперь позволяет **после разблокировки** выбрать одну из нескольких
записей с точным совпадением домена. При отмене выбора пароль не возвращается в браузер.
Добавлены два теста защиты от частичных совпадений доменов и URL со встроенными
учётными данными: 12 тестов успешно выполняются на Linux.

**Статус поставки:** Windows Hello, полная переработка интерфейса и независимый
аудит остаются нереализованными. Windows EXE в этом пакете нет. Перед подключением
браузера испытайте работу на отдельном тестовом хранилище.

### Безопасность репозитория

Не публикуйте `vault.dat`, ключевые файлы, резервные копии и мастер-пароль.
`.gitignore` исключает типовые локальные секреты, но **не заменяет проверку содержимого
коммита** перед публикацией.


## Pro 4.0: обновление интерфейса и экспериментальный Windows Hello

- Переработана верхняя панель основного окна и добавлен блок «Обзор хранилища».
- В разделе «Настройки» добавлено управление локальным быстрым входом Windows Hello.
- После первичного входа по мастер-паролю можно включить быстрый вход; отключение удаляет локальный токен.
- Мастер-пароль хранится только в **DPAPI-защищённом** виде в файле `hello_credential.json` в пользовательской папке; привязка к файлу и параметрам KDF предотвращает использование после смены мастер-ключа.
- **Модель угроз**: DPAPI НЕ привязывает секрет аппаратно к Windows Hello. Вредоносный код с правами текущего пользователя Windows потенциально способен получить его без подтверждения Hello. Это компромисс удобства, не полноценная passwordless-защита. Для максимальной защиты отключите быстрый вход.
- **Статус Windows Hello: экспериментальный.** Вызов `UserConsentVerifier.request_verification_async` в документации Microsoft предназначен для UWP, а настольным приложениям предписан interop-вызов с HWND. До внедрения и тестирования такого interop-вызова на Windows 10/11 успешная работа Hello **не подтверждена**. Основной мастер-пароль остаётся доступным.
- Установите `pip install cryptography winrt-Windows.Security.Credentials.UI` на Windows и запускайте `python moi_paroli.py`.
- `vault.dat` не изменён; тесты на текущей платформе не заменяют проверку на Windows.
