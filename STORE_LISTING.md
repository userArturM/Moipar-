## Название

Bitora Password Manager — локальное заполнение

## Краткое описание

Сохраняйте и заполняйте пароли через локальное приложение Windows. Подтверждение — мастер-паролем или Windows Hello.

## Полное описание

«Bitora Password Manager» связывает браузер с вашим локальным хранилищем паролей в Windows.

• Сохраняйте логин и пароль с HTTPS-сайта после подтверждения в отдельном окне приложения.
• Заполняйте поля из сохранённой записи. Если аккаунтов несколько, выберите нужный.
• Подтверждайте действие мастер-паролем или Windows Hello, если быстрый вход уже настроен в приложении.
• По желанию включайте предложение сохранения отдельно для каждого сайта.
• Сохраняйте новый пароль существующего аккаунта с историей изменений.

Для работы требуется приложение «Bitora Password Manager» для Windows: https://github.com/userArturM/Moipar-/releases/latest

Пароли хранятся в зашифрованном файле приложения. Мастер-пароль не передаётся браузеру. При заполнении повторно проверяются адрес и активная вкладка; форма не отправляется автоматически. Расширение не имеет сервера сбора паролей и не содержит рекламы.

Расширение поддерживает HTTPS-сайты. Заполнение iframe, нестандартных HTTPS-портов и некоторых нестандартных форм не поддерживается. Возможность установки в Яндекс Браузере зависит от совместимости и правил этого браузера.

## Single purpose

Save and fill website login credentials through the user's local MoiParoli Windows password vault, with separate native approval for each operation.

## Обоснование разрешений

| Разрешение | Назначение |
|---|---|
| activeTab | Работа с вкладкой, на которой пользователь открыл расширение; повторная проверка адреса перед заполнением. |
| scripting | Чтение видимых полей логина/пароля для сохранения и заполнение соответствующих полей после подтверждения. |
| nativeMessaging | Связь с отдельным локальным приложением Windows. |
| storage | Сохранение выбора сайтов, где пользователь включил предложение сохранения. Пароли не сохраняются в storage. |
| optional_host_permissions: https://*/* | Пользователь отдельно разрешает предложение сохранения на конкретном HTTPS-сайте. Разрешение на все сайты заранее не запрашивается. |

## Декларации обработки данных для проверки владельцем

Обрабатываются данные аутентификации, адрес сайта и относящиеся к входу поля страницы. Не отмечайте «не обрабатывает пользовательские данные»: обработка существует, хотя выполняется локально. Названия категорий в панели магазина могут меняться; сверяйте их смысл с PRIVACY.md и фактическим кодом. Продажи данных, рекламы, скоринга, удалённого исполняемого кода и сторонней аналитики нет.

URL политики: https://github.com/userArturM/Moipar-/blob/main/PRIVACY.md

Публикация требует регистрации и заполнения профиля разработчика. Имя владельца, контактный адрес и обязательные подтверждения заполняет владелец; они не выдуманы в этом пакете.

## Важный этап: ID магазина и подключение приложения

ZIP для магазина не содержит поля manifest.key. Текущий ID распакованной версии не следует считать будущим ID магазина. После загрузки ZIP как черновика получите Item ID и публичный ключ в панели магазина. До публикации нужно обновить штатную регистрацию native host для этого ID и проверить связь с приложением.

Для теста черновика существующий browser_host.exe поддерживает регистрацию дополнительного ID: `browser_host.exe --register --extension-id ID_ИЗ_ПАНЕЛИ`. Команда сохраняет ранее разрешённые ID. Для массового выпуска публичный ключ и ID магазина нужно включить в следующий согласованный выпуск приложения и расширения. Поле key в распакованной версии и browser_identity.py обновляются вместе; публичная публикация до этой проверки не выполняется.
